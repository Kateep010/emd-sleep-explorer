# JS 實作 vs PyEMD 交叉驗證

日期：2026-09-23

**比較對象**

- `js/emd.js`（本站瀏覽器端實作）：Huang et al. 1998 的 SD < 0.2 停止準則、單一 IMF 最多 50 次篩選、自然三次樣條包絡、兩端各鏡射 2 個極值（Rilling et al. 2003）。
- Python 套件 EMD-signal 1.10（PyEMD）：`spline_kind='cubic'`、`extrema_detection='simple'`、`nbsym=2`、`MAX_ITERATION=50`；PyEMD 除了能量比（即 Huang 的 SD）之外，還多一個 **IMF 條件：所有局部極大值 > 0、所有局部極小值 < 0**，因此通常會多篩幾次。

**資料**：`data/epochs.json` 的 16 個真實 30 秒 epoch（Sleep-EDF SC4002E0，Fpz-Cz）。

**為什麼不期待逐點相同**：EMD 沒有唯一解，停止準則、樣條種類（自然 vs. not-a-knot）與邊界處理都會改變 IMF 的能量在相鄰階之間的分配。因此這裡比較的是各階 IMF 的相關係數與平均瞬時頻率，以及「高頻合計（IMF1–3）」與「低頻合計（IMF4 以後）」的一致性。此外，`tests/test_emd.mjs` 另以有解析解的訊號（純音、雙音、完備重建）驗證本站實作的正確性。

## 結論

1. 把停止準則對齊之後，前三階 IMF 的逐階相關係數中位數由 0.69 提高到 0.83，高頻合計與低頻合計的相關係數中位數分別為 0.87 與 0.89：兩套獨立實作的差異主要來自**停止準則**，而非演算法本身。
2. PyEMD 因為多了極值符號條件而篩選更多次，IMF1 的平均瞬時頻率系統性偏高（例如 18 → 27 Hz）；這正是文獻所說「過度篩選會把 IMF 推向純調頻、失去振幅意義」的現象，也解釋了為什麼本站預設沿用 Huang 1998 的 SD 準則並設上限 50 次。
3. 剩餘差異來自樣條種類（本站為自然三次樣條，PyEMD 為 SciPy 的 not-a-knot 三次樣條）與邊界延伸細節；在 30 秒 epoch 兩端最明顯。

重跑：`node tools/dump_imfs.mjs js.json [strict]`、`python tools/pyemd_run.py`（需 `pip install EMD-signal`）、`python tools/xcheck_pyemd.py js.json py_imfs.json`。
